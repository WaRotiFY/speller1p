# Локальный браузерный режим: окно экспериментатора и окно участника

## Два окна

Сервер слушает только `127.0.0.1` и отдаёт две страницы:

| Адрес | Кто смотрит | Что там |
|---|---|---|
| `http://127.0.0.1:8765/operator` | экспериментатор | настройки блоков, запуск, пауза, стоп, живые распределения и предсказания, журнал эпох |
| `http://127.0.0.1:8765/` | участник | матрица 6×6, следующий символ, набранный и исправленный текст |

Окна синхронизированы через сервер. Каждое держит длинный запрос `GET /api/live` и получает новое состояние сразу после любого изменения: старта, паузы, вспышки, нажатия, решения детектора, остановки. Окно участника отправляет на сервер начало эпохи, номер каждой вспышки и каждое нажатие (`POST /api/progress`). Поэтому экспериментатор видит, как распределение меняется прямо во время вспышек. Эти сообщения прогресса нужны только для наблюдения и в журнал не пишутся. В журнал, как и раньше, пишется полная эпоха после `POST /api/epoch`.

Одновременно идёт одна сессия. Новую можно начать только после остановки текущей.

## Сценарий

1. Экспериментатор открывает `/operator` и нажимает «Открыть окно участника». Окно участника лучше перенести на второй монитор. Если монитор один, перед набором щёлкните в окне участника: пробел принимает только оно.
2. В карточке «Сессия» задаются ID участника (латиница, цифры, `_`, `-`), необязательный ID эксперимента и задание. Задание — это фраза из `data/tasks_ru.txt`, своя фраза или свободный набор без цели. Сессия с ID эксперимента пишется в `runs/gui/<experiment_id>/`.
3. Базовый профиль — один из `configs/gui_*.yaml`. Поля «Экспериментальных блоков» заполняются из него. Изменённые поля отмечаются точкой, рядом показывается значение из профиля.
4. «Начать сессию». Окно участника само начинает эпохи. Пока идёт сессия, настройки зафиксированы: полный снимок конфигурации записан в `config.yaml` сессии.
5. «Пауза» действует между эпохами: текущая эпоха доигрывается, следующая начнётся после «Продолжить». Паузы пишутся событиями `session_paused` / `session_resumed`.
6. «Стоп» закрывает запись и проверяет её целостность. Причина остановки — `operator_stopped`. Если цель набрана, сессия закрывается сама с причиной `target_finished`.

## Какие блоки меняет экспериментатор

Список совпадает с «Экспериментальными частями» проекта. К нему добавлены пункты, которые ТЗ требует менять: тайминги, режим с БЯМ и без БЯМ, парадигма. Браузер может изменить только эти ключи (`eeg_speller/web/settings.py`). Остальная конфигурация берётся из профиля без изменений.

| Блок | Ключи | Эксперимент |
|---|---|---|
| Режим и парадигма | `mode.llm`, `stimulus.paradigm` | REQ-PERF-04, NEED-F-03 |
| Стимуляция | `stimulus.flash_ms`, `isi_ms`, `pause_ms` (шаг 10 мс, диапазоны MA-33), `epoch.n_repetitions` | EXP-05, REQ-CONF-01 |
| Модель сигнала | `gui.response_hit`, `gui.response_false_alarm` — насколько декодер доверяет нажатию | EXP-08 |
| Быстрая БЯМ и контекст | `fast_llm.backend`, `model_id`, `context_source`, `word_prediction.n_max` | EXP-01, EXP-07 |
| Слияние | `fusion.strategy`, `alpha`, `beta`, `lambda` | EXP-04 |
| Детектор | `detector.mode`, `tau`, `max_retries`, `cold_start_symbols` | EXP-06 |
| Медленная БЯМ и коррекция | `slow_llm.trigger`, `every_k_symbols`, `window_words`, `min_context_words`, `strict_word_count`, параметры mock | EXP-02, EXP-03 |

Сочетание настроек можно сохранить кнопкой «Сохранить как профиль». Появится `configs/gui_<имя>.yaml`, который наследует базовый профиль и содержит только изменённые ключи. Существующие файлы не перезаписываются. Так удобно заготовить условия «с БЯМ» и «без БЯМ» и выбирать их для каждого участника.

Облачные модели в браузерном режиме выключены (`llm.allow_remote: false`, Q-33). Настоящую БЯМ для коррекции можно подключить локально: бэкенд `local_openai` обращается к OpenAI-совместимому серверу только на `127.0.0.1` (Ollama, `llama-server`, LM Studio). Готовый профиль — `gui_llm.yaml`, установка модели — README, раздел 7. Бэкенду `hf_causal` нужны `transformers` и `torch` (`uv pip install -e .[hf]`) и заранее скачанная модель. Если чего-то нет, сессия не начнётся, а окно экспериментатора покажет причину.

## Что видно во время испытания

- **Сводка:** эпохи, выбранные символы, точность выбора относительно цели, совпадение с целью, активное время без пауз и оперативная скорость. Это оценки для наблюдения. Метрики для отчёта считаются по `events.jsonl` модулем `evaluation`.
- **Текущая эпоха:** зеркало матрицы с текущей вспышкой и нажатиями, номер вспышки, лидер апостериорного распределения, его уверенность и порог τ. Подпись говорит, что сделает детектор: выберет символ, повторит эпоху (abstain) или выберет с меткой «неуверенно» (label).
- **Распределения:** три тепловые карты 6×6 — prior быстрой БЯМ, правдоподобие по нажатиям и апостериорное распределение после слияния. Правдоподобие и апостериорное распределение пересчитываются после каждой вспышки. Переключатель показывает текущую или последнюю завершённую эпоху.
- **Предсказания:** слова-кандидаты быстрой БЯМ для текущего контекста, последнее решение детектора, кнопка Qwen (если сервер запущен с моделью).
- **Текст:** цель с курсором, первичный текст с подсветкой несовпадений, исправленный текст; список вызовов медленной БЯМ с окном «до → после».
- **Журнал эпох:** цель, выбор, уверенность, отрыв, вероятность цели до и после слияния, ранг цели, число нажатий, время расчёта prior.

## Qwen

Кнопка «Предложить продолжение» в окне экспериментатора использует локальный Qwen2.5-0.5B-Instruct GGUF через CPU-сборку `llama-cli`, **если** сервер запущен с `--qwen-model` и `--qwen-cli`. В выборе символа Qwen не участвует, для этого используется prior быстрой модели. Модель не загружается из сети, файл должен существовать заранее.

## Запуск

```bash
.venv/bin/python -m eeg_speller.web.server --port 8765 --output runs/gui
```

Откройте `http://127.0.0.1:8765/operator`. Для Qwen добавьте `--qwen-model /absolute/path/to/qwen2.5-0.5b-instruct-q4_0.gguf --qwen-cli /absolute/path/to/llama-cli`.

## API

| Метод и путь | Кто вызывает | Назначение |
|---|---|---|
| `GET /api/operator/init` | экспериментатор | профили, задания, схема блоков |
| `GET /api/profile?name=` | экспериментатор | значения блоков в профиле |
| `GET /api/live?role=&since=&timeout=` | оба | длинный опрос; участник получает облегчённый снимок без распределений |
| `POST /api/start` | экспериментатор | `{profile, participant_id, experiment_id, task, settings}` |
| `POST /api/pause`, `POST /api/stop` | экспериментатор | пауза и остановка |
| `POST /api/preset` | экспериментатор | сохранить `gui_<имя>.yaml` |
| `POST /api/progress` | участник | `epoch_begin`, `flash`, `hit`, `flashes_done` |
| `POST /api/epoch` | участник | нажатия за эпоху; `epoch_id` защищает от двойной отправки из двух окон |

## Границы режима

Нажатия клавиатуры — контролируемая имитация бинарной физиологической реакции, а не ЭЭГ. Время вспышки задаёт браузер участника, поэтому точность ограничена планировщиком страницы и частотой монитора. Прототип не подключает реальную шапку, не калибрует участника и не доказывает метрики ТЗ на людях.
