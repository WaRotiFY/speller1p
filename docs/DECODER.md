# Декодер ЭЭГ: пример P300, EDF и LSL

Декодер — отдельный процесс. Он читает ЭЭГ и метки стимулов и присылает спеллеру правдоподобие символов (`SpellerLikelihood`, см. [`stimulus_kit/CONTRACT.md`](../stimulus_kit/CONTRACT.md), раздел 3). В комплекте есть пример:

- `stimulus_kit/decoders/p300_lsl_decoder.py` — P300-декодер для любого LSL-потока ЭЭГ;
- `stimulus_kit/tools/edf_to_lsl.py` — проигрыватель EDF-записи в LSL, который ведёт себя как живой усилитель;
- `python -m eeg_speller.physiology.edf_demo` — генератор синтетической ЭЭГ и обученной модели для проверки без оборудования;
- `python -m eeg_speller.physiology.calibrate` — калибровка модели по своей размеченной записи.

Настройки декодера (каналы, фильтры, модель, LSL-поток) лежат в блоке `physiology` профиля `configs/p300_decoder.yaml`.

## Проверка без оборудования

```powershell
uv pip install -e ".[external,eeg]"
uv run --no-sync python -m eeg_speller.physiology.edf_demo --text "привет"
uv run --no-sync python scripts/run_external_demo.py edf
```

Первая команда создаёт в `runs/edf_demo/` такие файлы:

| Файл | Назначение |
|---|---|
| `calibration.edf`, `calibration_labels.json` | отдельная синтетическая запись для обучения и её разметка |
| `p300_model.json` | обученная модель |
| `test.edf` | 8 каналов при 256 Гц и метки стимулов; в сигнале закодирован текст `--text` |
| `expected_test_only.json` | ожидаемый текст для проверки человеком; спеллер и декодер его не читают |

Вторая команда запускает спеллер, декодер и проигрыватель EDF как отдельные процессы. Через минуту-полторы в консоли появится набранный текст.

Синтетический сигнал содержит шум, альфа-ритм, дрейф и вызванные ответы. Он проверяет программную цепочку, а не точность на человеке.

## Что делает пример декодера

Для каждой метки стимула из `SpellerStimuli` декодер:

1. берёт окно ЭЭГ −200…800 мс;
2. отбрасывает окно, если амплитуда превышает `artifact_uv`;
3. фильтрует сигнал полосой 0,5–15 Гц;
4. для каждого канала считает среднюю амплитуду 250…500 мс относительно фона −200…0 мс;
5. по откалиброванной модели (небольшой Gaussian LDA) получает отношение правдоподобий «целевой / нецелевой стимул»;
6. прибавляет это отношение всем символам стимула.

После каждого обработанного стимула он присылает обновление, после последнего — с `final=true`. Если ни одного годного окна не набралось, обновление помечается `usable=false`, и спеллер повторит эпоху.

Время меток переводится в часы LSL того компьютера, где работает декодер, поэтому окна вырезаются по тем же часам, что и отсчёты ЭЭГ.

## Свой усилитель

1. **LSL-поток.** У усилителя должен быть LSL-поток: встроенный, через мост производителя или через приложение из набора LSL Apps.
2. **Профиль.** Скопируйте `configs/p300_decoder.yaml`, укажите свои каналы и поток:

```yaml
inherits: p300_decoder.yaml
physiology:
  channels: [Cz, Pz, P3, P4]
  model_path: runs/my_device/p300_model.json
  source:
    kind: lsl
    stream_field: name          # или source_id
    stream_value: MyAmplifier
    units: uV
    channel_aliases: {Cz: EEG-Cz, Pz: EEG-Pz, P3: EEG-P3, P4: EEG-P4}
```

   Частота берётся из метаданных потока. Если в потоке нет названий каналов, задайте `source.channel_order`. Единицы указываются явно.

3. **Калибровка.** Запишите сессию с известными целями (copy-spelling с подсказкой), сохраните EDF с аннотациями `speller/<epoch>/<flash>/<row|column|symbol>/<index>/<repetition>` и разметку вида `[{"epoch_id": 0, "flash_id": 0, "is_target": true}, …]`. Затем запустите:

```powershell
uv run --no-sync python -m eeg_speller.physiology.calibrate --profile configs/my_device.yaml --edf runs/my_device/calibration.edf --labels runs/my_device/calibration_labels.json --output runs/my_device/p300_model.json
```

   После смены электродов или параметров обработки модель нужно калибровать заново: декодер откажется загружать несовместимую модель.

4. **Запуск во время сессии.**

```powershell
uv run --no-sync python stimulus_kit/decoders/p300_lsl_decoder.py --profile configs/my_device.yaml
```

## Время и точность

- **Метки стимулов** ставит модуль стимуляции сразу после `flip` в часах LSL. Через сеть LSL пересчитывает их в часы приёмника, поэтому задержка доставки на них не влияет.
- **Задержка монитора** между `flip` и реальным свечением постоянна, но неизвестна. Её измеряют фотодиодом: ключ `--photodiode` в примерах рисует белый квадрат в углу экрана. Измеренную задержку модуль добавляет к метке.
- **Несколько компьютеров в сети.** Для LSL используйте конфигурацию сети. Для проверки на одном компьютере достаточно `tests/lsl_local.cfg`: `$env:LSLAPICFG = "tests/lsl_local.cfg"`. Подробнее — [настройки LSL](https://labstreaminglayer.readthedocs.io/info/lslapicfg.html).
