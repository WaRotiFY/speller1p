# Источник ЭЭГ: проигрывание чужих записей и живой усилитель

Физиология — три отдельные программы. Они ничего не знают друг о друге и связаны только потоками LSL:

| Часть | Что делает | Пишет | Читает |
|---|---|---|---|
| Стимуляция (`stimulus_kit/modules/…`) | рисует экран испытуемого | `SpellerStimuli` | `SpellerControl` |
| **Источник ЭЭГ** (`stimulus_kit/tools/eeg_source.py`) | отдаёт ЭЭГ: живую или из файла | `SpellerEEG` | — |
| Декодер (`stimulus_kit/decoders/…`) | вырезает окна, классифицирует | `SpellerLikelihood` | `SpellerEEG`, `SpellerStimuli` |

Декодер не отличает запись от живого усилителя: в обоих случаях он читает поток `SpellerEEG` и вырезает окна по LSL-времени вспышек. Что на входе, видно в метаданных потока (`origin`: `replay` или `live`).

**Чем отличается от `edf_to_lsl.py`.** `edf_to_lsl.py` проигрывает только EDF, записанные самим спеллером (аннотации `speller/<эпоха>/…`), и идёт за эпохами живого спеллера. `eeg_source.py` рассчитан на чужие записи, например записи лаборатории, где запись и анализ — разные программы. Метки берутся из аннотаций EDF+ или из канала триггера, а карта меток (JSON) переводит коды лаборатории в сообщения контракта. Кроме того, здесь есть режим `live` для усилителя. Читаются EDF, EDF+ и BDF.

## 1. Что лежит в файле

```powershell
uv run --no-sync python stimulus_kit/tools/eeg_source.py info запись.edf
```

Выводит каналы с частотой и единицами, каналы, похожие на триггер, и аннотации, сгруппированные по шаблону (цифры заменены на `#`). По этому выводу заполняют карту меток.

## 2. Карта меток

Шаблон — `stimulus_kit/tools/markers_TEMPLATE.json`; готовая карта для EDF самого спеллера — `stimulus_kit/tools/markers_speller_edf.json`.

| Ключ | Что это |
|---|---|
| `symbols`, `layout` | клавиатура, которую видел испытуемый в этой записи; уходит в `SpellerStimuli` событием `keyboard` |
| `epoch_start`, `epoch_end` | шаблоны (`*`, `?`) меток начала и конца набора одной буквы |
| `flash` | правила-регулярки по порядку, срабатывает первое: `row_from_group`, `col_from_group`, `symbol_from_group` (номер из группы, `offset` — с какого числа нумерация), `symbols_from_group` (буквы прямо в метке, `sep` — разделитель), `symbols` (фиксированный список); `epoch_group` — номер эпохи прямо в метке |
| `cue` | метка с целевой буквой. Идёт только в `SpellerReplayMarkers`: по контракту цель модулям не передаётся |

Если меток начала эпохи нет и номера эпохи в метках тоже нет, все вспышки считаются одной эпохой. Разбить файл можно ключами `--start/--stop`.

## 3. Проигрывание записи

```powershell
# только ЭЭГ и сырые метки
uv run --no-sync python stimulus_kit/tools/eeg_source.py replay запись.edf

# запись играет роль модуля стимуляции (клавиатура и вспышки в SpellerStimuli)
uv run --no-sync python stimulus_kit/tools/eeg_source.py replay запись.edf --marker-map карта.json --as-stimulus

# без спеллера: запись сама начинает эпохи в SpellerControl
uv run --no-sync python stimulus_kit/tools/eeg_source.py replay запись.edf --marker-map карта.json --as-stimulus --as-control
```

Декодер запускается так же, как с живым усилителем, но с именем потока:

```powershell
uv run --no-sync python stimulus_kit/decoders/p300_lsl_decoder.py --eeg-name SpellerEEG --model путь/p300_model.json
```

- **Время.** ЭЭГ уходит кусками по 20 мс в исходном темпе. Метка каждого отсчёта — момент старта плюс его время в файле. Метки вспышек ставятся в той же шкале, поэтому окно декодера совпадает с записью до отсчёта.
- **Метки** все идут в поток `SpellerReplayMarkers` как есть: `{"label", "code", "onset_s", "duration_s"}`. Ключ `--trigger-channel TRIG` берёт метки из фронтов канала триггера; числовые аннотации тогда отбрасываются (обычно это копия того же канала), текстовые остаются.
- **Каналы.** `--channels` или `--drop`. Каналы напряжения отдаются в мкВ; фотодиод, триггер и прочие — как в файле, с типом `AUX`. В одном потоке одна частота: каналы с другой частотой пропускаются с предупреждением.
- **Ожидание.** Перед стартом проигрыватель до `--wait` секунд (по умолчанию 10) ждёт, пока подключатся декодер и, при `--as-control`, слушатели команд.
- **`--speed 4`** — быстрее реального времени. Метки остаются в шкале файла, поэтому окна декодера не искажаются. Живой спеллер так запускать нельзя.

## 4. Живой усилитель

```powershell
uv run --no-sync python stimulus_kit/tools/eeg_source.py live --find type=EEG        # или name=<поток усилителя>
```

Находит поток усилителя и переотправляет его как `SpellerEEG` с исходными метками времени (с поправкой часов LSL). Раз в 10 с пишет фактическую частоту и число разрывов. `--dejitter` сглаживает метки по номинальной частоте; включать его стоит, только убедившись, что фактическая частота равна номиналу.

## 5. Проверка

| Что проверяли | Результат |
|---|---|
| Сквозная цепочка: `edf_demo` → `eeg_source.py replay --marker-map markers_speller_edf.json --as-stimulus --as-control` → `p300_lsl_decoder.py --eeg-name SpellerEEG` | 240 вспышек из 240, 10 эпох, декодер набрал «привет мир» без ошибок |
| `tests/test_eeg_source.py`: импульс фотодиода относительно метки вспышки | ровно в отсчёте метки во всех вспышках |
| Там же: контракт | первым идёт `keyboard`, номера эпох и `done` по эпохам, `epoch_start` без цели |
| Там же: канал триггера | коды совпадают с записанными, текстовые аннотации сохранены |
| live: задержка от усилителя до читателя `SpellerEEG` | медиана 8 мс, 95 % — 11 мс |
| live: ошибка метки времени отсчёта | < 0,05 мс |

## 6. Ограничения

- **Запись не реагирует на спеллер.** В записи эпохи шли с фиксированным числом повторений. Если спеллер решит остановиться раньше или выберет другую букву, запись этого не узнает. Replay честно проверяет декодер и слияние с языковой моделью; досрочную остановку — только «обрезанием»: сколько вспышек хватило бы.
- **С живым спеллером** (`--as-stimulus` без `--as-control`) номера эпох берутся из файла. Совпасть с эпохами спеллера они могут только при одинаковом порядке; для этого случая есть `edf_to_lsl.py`.
- **Задержка монитора** в старых записях неизвестна, если не было фотодиода. Если она была постоянной, классификатор её «выучит» при калибровке на тех же данных.
- **Аннотации EDF+.** В файле на одну запись данных помещается ограниченное число аннотаций; программы записи, которые этого не учитывают, молча теряют метки. `info` показывает, сколько меток реально в файле.
