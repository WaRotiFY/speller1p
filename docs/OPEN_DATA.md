# Открытые данные и готовый внешний анализатор

Проверка идеи «физиологию можно подключить готовую»: реальная запись чужой лаборатории идёт через настоящий спеллер. Модуль стимуляции проигрывает запись, готовый P300-конвейер из сторонней библиотеки её анализирует, а спеллер сливает правдоподобие с языковой моделью, решает, когда остановиться, и выбирает букву.

```
                         SpellerControl: epoch_prepare / epoch_start / stop / result
спеллер (окно оператора) ─────────────────────────────────────────┐
     ▲  SpellerLikelihood                                          ▼
external_pipeline_decoder.py ◄── SpellerEEG ─── модуль eeg_replay (экран испытуемого)
     ▲                        ◄── SpellerStimuli ─┘   └─ bnci2014_008_A01.edf + markers_bnci2014_008.json
     └── запускается модулем; модель runs/models/*.joblib (если нет — обучается на первых символах записи)
```

## Данные: BNCI 2014-008

- **Участники и запись:** 8 пациентов с БАС, 8 каналов (Fz Cz Pz Oz P3 P4 PO7 PO8), 256 Гц.
- **Парадигма:** матрица 6×6, строки и столбцы. На каждого участника 35 символов по 120 вспышек, то есть 10 повторений, как в VER-EXP-05. Вспышка 125 мс, SOA 250 мс.
- **Источник:** Riccio et al. 2013, doi:10.3389/fnhum.2013.00732. Лицензия CC BY-NC-ND 4.0.

```powershell
uv run --no-sync python stimulus_kit/tools/open_data/get_bnci2014_008.py          # A01
uv run --no-sync python stimulus_kit/tools/open_data/get_bnci2014_008.py all      # все восемь
```

Скрипт качает файлы `A0x.mat` с <https://bnci-horizon-2020.eu/database/data-sets> (008-2014). Если сайт недоступен, он берёт побайтную копию с GitHub (`AyanaMussabayeva/P300-Speller-BCI-Research`). Каждый файл сверяется по SHA-1, затем переводится в EDF+ в `data/bnci2014_008/`; эта папка в `.gitignore`.

Аннотации EDF+:
- `epoch` — начало символа;
- `target:x` — цель, идёт только в журнал проигрывания, декодер и спеллер её не получают;
- `R1…R6`, `C1…C6` — вспышки.

Клавиатура строчная (`a…z`, `1…9`, `_`), как у спеллера, который переводит задание в нижний регистр. Набранный текст по разметке: `2baci5rosezuppagattomenteviolarebus`. Первые 15 символов идут на калибровку, символы 16–35 (`gattomenteviolarebus`) — на проверку.

## Запуск со спеллером

Порядок действий — в README, раздел 3, «Реальная ЭЭГ вместо испытуемого». Окно оператора: язык English, модуль одной из записей, задание из списка (`BCI2B_TEST` или `BNCI008_TEST`). Без браузера (английская запись, профиль `configs/ext_replay.yaml`: English, 4-грамма `en_char4`, словарь каждые 20 символов):

```powershell
uv run --no-sync python -m eeg_speller.external --profile configs/ext_replay.yaml --target "foodmoothampiecaketunazygot4567"
uv run --no-sync python stimulus_kit/modules/eeg_replay_bci2/main.py     # второе окно
```

Что делает модуль `stimulus_kit/modules/eeg_replay`:
- **Сопоставление.** Эпохе спеллера соответствует следующий символ записи. Отсчёты ЭЭГ идут от 0,5 с до первой вспышки до 1 с после последней, в темпе записи, со свежими метками LSL. Метка вспышки ставится в тот момент, когда до неё доходит запись. После каждых 12 вспышек модуль шлёт `trial_done`, в конце — `done`.
- **Досрочная остановка.** Если спеллер прислал `stop`, вспышки обрываются, а ЭЭГ ещё 1 с идёт для последних окон декодера.
- **Повтор.** Если эпоха прервана (нет правдоподобия, отмена, Esc), спеллер повторяет позицию, и модуль проигрывает тот же символ записи. Когда символы записи кончаются, эпоха отменяется, и сессию нужно завершить вручную.
- **Декодер.** Модуль запускает `external_pipeline_decoder.py run` сам, вывод пишется в `logs/decoder.txt` папки сессии. Первый символ модуль начинает, только когда декодер подключился к `SpellerEEG`.
- **Настройки** (`settings.json`): `edf`, `marker_map`, `pipeline`, `model`, `calibration_symbols`, `first_symbol`, `speed`, `show_cue`, `show_window`, а также времена и цвета экрана.

Язык сессии для обеих записей — English: клавиатура латинская. Для BNCI 2014-008 БЯМ лучше выключить, потому что слова там итальянские. Если выбрать русский язык, русская модель латинские буквы считает равновероятными, а пробелу отдаёт почти всю массу; спеллер предупредит, что клавиатура модуля на другом языке.

## Анализатор: `stimulus_kit/decoders/external_pipeline_decoder.py`

Анализ делает готовый конвейер из сторонней библиотеки. Файл только вырезает окна по меткам и складывает оценки вспышек в правдоподобия символов. Он работает по протоколу `speller-link@2`: учитывает `epoch_cancelled` и присылает `through_flash`.

| `--pipeline` | Что внутри |
|---|---|
| `xdawn_riemann` | pyRiemann: XdawnCovariances → TangentSpace → LogisticRegression, 1–20 Гц, 0–800 мс. Эталонный P300-конвейер бенчмарка MOABB |
| `rlda` | scikit-learn: 0,5–10 Гц, 0–800 мс, прореживание до ~20 Гц, LDA со сжатием (Krusienski 2008; то же делает `CMDModelRLDA` в MEDUSA) |

Оценка вспышки — логарифм отношения правдоподобий «цель / не цель» без априорной доли целей. Символ получает сумму оценок вспышек, в которых он был.

```powershell
$D = "stimulus_kit/decoders/external_pipeline_decoder.py"
$M = "stimulus_kit/tools/open_data/markers_bnci2014_008.json"
$E = "data/bnci2014_008/bnci2014_008_A01.edf"
uv run --no-sync python $D calibrate $E --marker-map $M --train-epochs 15 --out runs/models/A01.joblib
uv run --no-sync python $D evaluate  $E --marker-map $M --model runs/models/A01.joblib --skip-epochs 15
```

`evaluate` печатает:
- AUC и сбалансированную точность по вспышкам;
- точность символа после 1…10 повторений;
- `early_stop` — что сделало бы правило остановки спеллера (порог `--stop-confidence`, по умолчанию 0,99, не раньше 12 вспышек): точность и среднее число вспышек.

`calibrate --fit-scale` уменьшает оценки на множитель, подобранный кросс-валидацией по калибровочным символам. Вероятности становятся честнее, но до остановки нужно больше вспышек. На этих данных точность это не повысило, поэтому по умолчанию масштаб равен 1.

**Устойчивость.** Если декодер подключился к ЭЭГ позже первых вспышек, окна до начала его буфера помечаются непригодными, и он идёт дальше. Иначе правило «оценивать вспышки строго подряд» (`through_flash`) навсегда остановило бы символ. У примера `p300_lsl_decoder.py` этой защиты нет. Если декодер присоединился посреди символа, буквы, которых он ещё не видел во вспышках, получают нулевое накопление.

Ошибки в основном «соседние»: перепутана строка или столбец.

На сильном сигнале (BCI Competition II, d′ = 1,95; две английские фразы) ошибок нет ни в одной настройке, а 4-грамма сокращает число вспышек с 39 до 28 на символ: +33 % скорости.

Выводы:
- **Быстрая БЯМ помогает:** при пороге 0,99 скорость растёт на 48–50 % без потери точности. Это выше порога ТЗ (+20 %, REQ-PERF-04), но получено на полусинтетике, а не на людях.
- **Корректор при пороге 0,99 почти не нужен.** Ошибок 0–2 %, и это ошибки, в которых ЭЭГ была уверена: у правильной буквы остаётся доля процента. Оценки декодера по отдельной вспышке откалиброваны честно (наклон калибровки 0,91–1,02), так что самоуверенность тут ни при чём. Словарь такое не исправляет: «dold» остаётся «dold», хотя по смыслу это «cold». «thank» набирает 79,6 % при пороге замены 80 %. Нужна БЯМ по смыслу.
- **При пороге 0,9** набор быстрее, но ошибок 12 %. На слабом сигнале быстрая БЯМ тут добавляет ошибок: априорное распределение перетягивает, отсюда «forta whole». Словарь исправил 5 слов (glast→glass, seather→weather, thatk→thank; lighte→lights и onle→only — неточно), CER 12,3 % → 11,5 %.
- **Корректор-БЯМ** (`ngram+api`, Ollama или облако) здесь не проверялся: в этой среде нет ни модели, ни ключа. Команда для проверки — в README, раздел 3.

**К REQ-PERF-01.** Если «точность бинарной классификации» понимать по отдельной вспышке, получается 75–77 %, то есть ниже 80 %. Если по символу после 10 повторений — 93–96 %. Это пациенты с БАС; на здоровых участниках обычно выше. Формулировку стоит уточнить (см. `OPEN_QUESTIONS`).

## Ловушка: единицы

`eeg_speller.physiology.sources.LSLSource.window()` отдаёт **вольты**, а `eeg_source.load()` и EDF — **микровольты**. Модель, обученная на файле, получит в онлайне сигнал в 10⁶ раз меньше и почти постоянные оценки. Причём из-за шума округления часть букв всё равно «угадывается». Внешний декодер переводит окно обратно в мкВ (`w * 1e6`). Любой новый декодер на `LSLSource` должен делать так же или обучаться на вольтах.
